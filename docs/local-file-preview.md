# Local file preview (initial Ember slice)

Ctrl + primary click on a detected local file reference opens a read-only right sidebar candidate. Because terminal output can come from a remote proxy even when its foreground process is local, this first slice **does not automatically read the file**. The user selects **Preview local file** after inspecting the candidate and local base directory. Known SSH and non-interactive sessions are rejected. A foreground application with mouse reporting enabled retains the click; the host does not take it for preview.

The base directory is captured from the originating PTY foreground process at pointer press, not from terminal-controlled OSC 7 or the assistant process cwd. A delayed click is cancelled on session changes as before. A preview is shown only for its originating session. File reads and image decoding happen on one worker, so slow filesystems cannot create an unbounded thread queue.

Supported initial scope:

- Existing absolute, `./`, `../`, `~/` references and simple bare source references such as `src/App.tsx:12:3` and `README.md`.
- UTF-8 text including TSX, Markdown, HTML and SVG is displayed as inert selectable source. No JavaScript, shell, HTML/webview, Markdown commands, external opener or remote fetch is invoked.
- PNG, JPEG and static WebP raster previews identified by content signatures, not file extensions. Animated WebP, Markdown rendering, syntax highlighting, exact column highlighting, OSC 8 file URIs and quoted filenames containing spaces are not implemented in this slice.
- Exact filenames win over `:line[:column]` suffix interpretation. Suffix fallback is allowed only on NotFound. A parsed line suffix scrolls to and highlights the numbered line after loading. Out-of-range lines show an explicit notice instead of silently clamping. Column metadata is displayed, not interpreted as a byte or glyph offset. Literal colon filenames do not trigger a jump.
- Files must be regular files. Final symlinks are rejected; parent directory symlinks may resolve normally. On Linux an inert `O_PATH` handle is checked before reopening that held inode through `/proc/self/fd`, avoiding a device-open side effect and path replacement retargeting. Other platforms precheck the path and validate the read descriptor, but do not provide the same race-proof device-open guarantee. This is explicit local file selection, not a project-directory sandbox.
- Text is capped at 1 MiB and encoded raster data at 8 MiB. All raster dimensions are checked before pixel decoding: each side at most 4096 and at most 4M pixels. WebP additionally validates chunk sizes, inner VP8/VP8L dimensions against its extended canvas, and rejects animation/multiple images before codec entry. The decoder is configured with a 64 MiB allocation budget after reserving decoded output bytes; image codec support for allocation limits is best-effort, **not a hard process RSS or CPU-time bound**. RGBA and GUI texture conversion add their own bounded storage. Binary and unsafe control characters are rejected. Reads detect files growing past the budget.

Text rows are virtualized: only the viewport rows are laid out; a new file gets a fresh scroll identity. Returning from another tab does not replay the initial seek.

Validation: loader and parser unit tests, exact-name/fallback and no-read-before-confirmation tests, detector regression, full production binary compile, and headless production egui frames covering a confirmation click with a real file worker, a Close click, hidden-session isolation, and line 1500 of a 2000-line source. Raster tests additionally cover JPEG, transparent lossless and lossy/extended WebP, malformed signatures, oversized headers/encoded files, hidden inner dimensions and animated containers. These use synthetic egui events, not a desktop input stack. These are not evidence of actual Codex CLI native GUI acceptance or five-terminal rollout.
