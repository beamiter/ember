# Owned public targeting for the existing E03 gate

The a96 hosted public-control proof established real scope Pressed transitions,
focus-away/back, exact physical query readback and zero PTY input under the same
foreground collector. This fixture-only successor applies that targeting route
to the existing raw and snapshot scenarios. It is not native search acceptance.

Each scenario retains a separate fresh HOME/app and now starts an isolated private
session/accessibility bus using the same explicit environment allowlist. Generated
E03 emitter paths are added explicitly. No host display, bus, accessibility settings,
clipboard or credentials are reused. The fixture uses system python3-dbus.

The opening chord remains one Ctrl+Shift+G. The named PID-owned Block Search frame,
editable Entry and scope controls must be unique, related and visibly bounded.
A fresh expected prior query is required (empty on the first open, then the last
verified process-lifetime intent). Query readiness requires observed focus. If
already focused, that state is recorded without invoking or claiming a transition.
If a known scope has focus, one public GrabFocus must return focus to the editor
while preserving scope intent and all target identities.

Physical Ctrl+A/type/copy remains the query-input path. The exact bytes copied from
the isolated fixture clipboard are now persisted, with SHA-256, expected query,
public editor Text, editor path and the matching tree filename. Wrong bytes are
also retained before failing. Query OCR and relative Latest/Out geometry are no
longer prerequisites or sources of query/scope coordinates.

Out targeting either records a uniquely already-pressed Out state without dispatch,
or requires a fresh opposing All/Cmd state, one public click and an observed Out
Pressed response on the identical controls. No no-op is claimed as a transition.

Search this retained output, Stop search, Restart this output and Earlier history
remain the only permitted semantic operation names. Each target requires a fresh
owned public-tree/screenshot/public-tree evidence bracket with exact name,
PushButton role, public action name/index, same picker ancestry and current bounds.
One public action is issued. A true response is recorded as pending the existing
search oracle; it is never itself successful search evidence. There is no Latest
fallback, cached rectangle, repeated action or private controller mutation.

Raw/snapshot input size/digest/PTY identity, 100k rows, 64 retained snapshots,
active-Stop plus retained-row claim, loading Return, explicit Stop, claim identity,
Restart/Complete, pointer result activation, final neighboring output-row navigation,
RSS sampling, polling timeouts and workflow 12-minute limit are unchanged. Exact public raw result/phase evidence and snapshot selected-result labels are
described below. Final real-output OCR stays strict. New evidence may reveal further fixture limitations;
this patch does not relax those oracles or certify any performance metric.

The public-control probe and its zero-byte PTY test remain separate. The actual
search gate must let its real synthetic emitters run normally. No production files
are changed. Activated-service exit remains explicitly unverified; existing Smoke
cleanup is always attempted even when group signaling fails.

## Exact public visible-state evidence repair (pending hosted acceptance)

Picker action selection now uses a fresh PID/bus/window-owned AT-SPI tree,
followed by one screenshot and a second owned tree. Exact role/name/action,
visible/showing states, picker/window bounds, target identity and bounds must
agree across the screenshot. The PNG hash is checked again after the second
read; image dimensions must contain the owned window. A same-label old image
cannot be reused. Evidence JSON records the actual target and PNG hash.

Snapshot navigation selects the unique selected public result ToggleButton (role
62, pressed state), whose label includes
the exact generated full output line and output-line context, excluding the query
Entry. There is no O/0 substitution or fuzzy matching. Its fresh bounded target
supplies pointer coordinates. Missing pre-capture targets can be observed until
the original 30-second budget; ambiguity, changed evidence or disappearance
across capture fails immediately. Every successful evidence bracket must finish
inside the remaining budget.

Raw retained-row hit identity, active Stop co-observation, rejected loading Return,
Stop/Restart and completion claims now use exact fresh public result/state evidence
with the same immutable screenshot bracket. Final neighboring real-output OCR
remains unchanged. Terminal output is not available in the recorded accessibility tree;
final navigation still requires exact target token plus the real neighboring row
in pixels. This change does not establish native acceptance or measure latency.


## Fresh 5704 evidence correction (pending hosted acceptance)

Actual hosted selected result nodes map to role62 ToggleButton, not role43
PushButton. Both snapshot and raw selection require the exact full Result label,
pressed state, Out scope, public click action, owner and visible picker bounds.
Snapshot label retains the complete generated line and output-line context.

Raw active evidence contains the exact selected retained-row result and Stop
control in ONE fresh tree, both stable before/after one immutable screenshot.
The claim includes token, retained-row number and result path. The same claim
must survive loading Return and Stop. Stopped activation requires Restart and no
Stop/Continue; completion requires exact generated coverage status, not a partial
or natural-limit result. Contradictory Stop/Continue/Complete states fail closed.
The active-observation deadline is shared from the original action and never
reset by a new observation: 9.5 seconds, unchanged from the operation budget.
No fuzzy OCR, query-only hit, cached target, input retry or budget extension.

The 5704 run reached 92,160 of 100,000 raw row decodes before its 9.5-second
operation limit. Full-completion feasibility at this workload remains unresolved;
this change does not reduce the 100,000 rows or extend the budget. Final real
neighboring-output OCR remains required and may expose a later fixture issue.
