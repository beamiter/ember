# Ember DECRQM ownership

The engine's existing Ember-compatible `semantics::dispatch_local` handles CSI
with final `p`, exactly `$` as the intermediate, and no prefix or `?`. It emits
one existing `Reply` effect. Ember applies that effect and its takeover observer
before the next event. The old production query arm and both mode-state helpers
are removed. No mode mutation or new public effect is introduced.

Compatibility includes first-parameter/default-zero lookup, ignored additional
parameters, origin and insert booleans as authoritative state, permanently-reset
ANSI 20, and unrecognized unsupported modes including 1016. The complete legacy
private-mode allowlist is retained. TerminalModes has no 4/6/1016 storage slots;
the tests do not pretend inserting those numbers creates stored bits.

## Independent baseline

`decrqm_provenance.json` identifies Ember 4f8f829e5d22a746f9654be44282989b394486ef
and core 4b189cb7d55fe00d4ee39e74a143fc09d044c772. Before extraction, actual
production `process_input` captured 67,944 snapshots: four rich seeds and every
feed in 75 input cases, all boundary subsets for inputs up to eight bytes, and
whole/bytewise/every single split for longer inputs. Primary/alternate screens
and inactive/active synchronized output are covered. Host titles, IME,
clipboard requests, notifications, colors, bell and paste grant are nondefault.

The golden preserves every captured lane, including parser carry, replies,
grid/hidden-grid, provenance, dirty/search revisions and observer latch. Exact
clock readings, sync-start Instant and paste expiry are compared directly;
nondeterministic timestamps are not serialized. This is not a claim that every
opaque host field is serialized.

The 118,729,033 original bytes are losslessly stored as a 4,214,630-byte
`jterm-oracle-intern-v1` file. Independent unpack reproduced exact SHA-256
`d9901aaf729e3e9ce1feae9943cf267a151aa1770db940781828fff9194a7329`.
The packed SHA-256 is
`e1174cffc78998fce6239ea43d7f9834a39c385fa33c261d101889016b56586c`.
No expected value was generated by the replacement semantics. Capture remains
ignored during normal tests; the frozen oracle and values are not regenerated.

A cfg(test)-only invocation adapter preserves old helper-level test entry points
by calling the actual engine dispatcher and parsing its Reply. It contains no
mode support table or semantic decisions. Production stream tests do not use it.

## Mutation evidence and boundaries

Pre-extraction source mutants for wrong origin owner, 1016 support, ANSI 20,
parameter choice and framing are killed by the original production golden.
Suppressing the helper observer alone survives because the outer parser also
observes fallback events. Suppressing both fallback observation sites is killed;
this nuance is retained rather than misreported. The new engine branch has one
immediate observer before `continue`.

Engine tests independently freeze the original lookup bodies and cover every
u16 mode, four origin/insert combinations, attempted stored/unset modes,
malformed routing and full state retention. Real candidate source mutants also
check unsupported selectors, prefix/intermediate matching, reply framing
and unintended state mutation. Ordinary tests separately cover final-byte
matching. Existing reset/query frozen samples stay intact.
The reset/query mutation runner now targets actual engine semantics through
private manifests, rather than searching for removed host helper boundaries.

Frost policy, GTK/VTE consumers, RIS, mode effects, clipboard authorization,
synchronized-output lifecycle, graphics and title policies remain host-owned.
No other consumer needs a pin update. Native exact-commit CI and desktop gates
remain separate from pure semantic parity and must be checked at publication.
